# 四板块讲解稿提示词（子任务 D）

> 位置：`src/server/llm/prompts/`；本文是该目录的说明书。
> 契约来源：`src/shared/types.ts` 的 `PromptSpec`、`src/server/llm/schema.ts` 的四个 zod schema。
> 自检：`npx tsx src/server/llm/prompts/_check.ts`（本地校验，不发起任何网络请求）。

## 一、文件与调用方式

| 文件 | 导出 | 说明 |
|---|---|---|
| `books.ts` | `booksPrompt` / `buildBooksUser` | 书籍学习 |
| `ai-tools.ts` | `aiToolsPrompt` / `buildAiToolsUser` | 前沿 AI 应用（GitHub 高星工具） |
| `markets.ts` | `marketsPrompt` / `buildMarketsUser` | 全球与中国金融 |
| `world.ts` | `worldPrompt` / `buildWorldUser` | 全球局势（每日 5 件大事） |
| `index.ts` | `PROMPTS: Record<SectionId, PromptSpec>`、`getPrompt(section)` | 汇总登记 |
| `_check.ts` | —— | 自检脚本：装配打印 + 契约测试 |

调用约定（供 `llm/client.ts` 与 `pipeline/*` 使用）：

```ts
import { PROMPTS } from './llm/prompts/index.js';

const prompt = PROMPTS['ai-tools'];
const user = prompt.buildUser(input);          // 组装事实输入
const payload = prompt.schema.parse(rawJson);  // zod 校验，失败即判生成失败
```

四个 prompt 的 `schema` 直接复用 `../schema.js` 里现成的 `BooksPayloadSchema` / `AiToolPayloadSchema` /
`MarketsPayloadSchema` / `WorldPayloadSchema`，因此 `parse` 通过即意味着入库字段齐全。

## 二、通用硬约束（四份提示词逐条写死）

1. **输出格式**：只输出一个 JSON 对象，字段与给定结构完全一致；禁止代码块围栏；禁止任何解释性前后文、Markdown 标题；
   回复首字符必须是 `{`，末字符必须是 `}`；字符串内换行写成转义形式（反斜杠加 n）。
2. **事实纪律**：只使用输入里给出的事实、标题与数字；不得凭记忆补充人名、数字、日期、机构或事件细节；
   事实与推断分开，推断必须用「可能 / 大概率 / 值得关注 / 倾向于认为 / 有不确定性」等措辞点明；无法确认的一律不提。
3. **普通人视角**：不堆术语；术语第一次出现必须紧跟一句大白话解释；多用具体场景和类比；一句话只讲一件事。
4. **长度**：summary 120–200 字；takeaways 3–5 条、每条 20–45 字；body 900–1500 字、段落间空行、段内可用 `**粗体**`；
   script 400–700 字、口语化、句子短。
5. **朗读适配**：script 不得出现表情符号、括号注释、Markdown 标记（`# * \` > -`）、网址；不得出现阿拉伯数字，
   数字写成中文读法（「12.3%」→「百分之十二点三」，「2026 年」→「二零二六年」）；不得有主持腔。
6. **板块专属**：见下文第三章各节。

> 字数口径：**去掉空白后的字符数**（含中文标点）。自检脚本与本文用同一口径。
> 每份 system 提示词结尾都有一段「收尾检查 · 必须在心里过一遍再输出」，让模型在输出前自查一次。

### 3.1 books 书籍学习

**板块要点**

- 一本书只讲一个核心概念，全篇围绕 `meta.coreIdea` 展开，不铺陈多观点。
- 必须从 `seedIdeas` 里挑一个：`meta.book` 写书名、`meta.author` 写作者；候选是概念就选最能讲清它的经典著作。
- `meta.discipline` 与输入学科一字不差；作者拿不准就换一个能确证的候选。
- 正文顺序：书在回答什么问题 → 核心概念是什么（配生活化例子）→ 为什么和你有关 → 今天能用上的一个动作。

### 3.3 markets 全球与中国金融

**板块要点**

- `meta.quotes` 与输入报价**逐字一致**：条目数量、顺序、symbol、name、price、changePct 全部照抄，不四舍五入、
  不补零、不改正负号、不增删条目；`meta.indices` 照抄 symbol、name、changePct，条目数量与顺序不变。
  user 消息里直接给出原始 JSON 便于照抄；指数块只输出 schema 需要的三个字段，即使调用方把带 `price` 的报价数组当指数传进来也不会多出字段。
- 只做解读，不补输入之外的价格、点位、财报数字与宏观数据。
- 重点是风险与不确定性：`meta.riskPoints` 至少两条，写清哪个变量还没定、什么情况会推翻当前判断。
- 不给投资建议：禁止「应该买入 / 建议加仓 / 该抄底 / 目标价」这类措辞，不预测点位。
- `meta.marketMood` 一句话不超过 30 字，客观不夸张。

## 四、如何判断生成结果不合格（检查清单）

命中任意一条即判**不合格**，交由上层重试（提示词层不做自动修补）。括号内是自检脚本里的对应断言。

### 4.1 通用（四个板块都查）

|---|---|---|
| 1 | 输出是且仅是一个 JSON 对象，首字符 `{`、末字符 `}` | 不合格 |
| 2 | 没有代码块围栏（```）、没有「好的」「以下是」之类的解释文字、没有 Markdown 标题 | 不合格 |

| 4 | 字段齐全且无多余字段：`title/subtitle/summary/takeaways/body/script/meta` | 不合格 |
| 5 | summary 120–200 字；takeaways 3–5 条且每条 20–45 字 | 超界即不合格 |
| 6 | body 900–1500 字，段落间用空行分隔，无 Markdown 标题符号 | 超界即不合格 |
| 7 | script 400–700 字，口语化、句子短 | 超界即不合格 |
| 8 | 事实纪律：没有输入之外的人名、数字、日期、机构、事件细节 | 不合格 |
| 9 | 推断与事实分开：判断句带「可能 / 大概率 / 值得关注 / 倾向于认为 / 有不确定性」 | 不合格 |
| 10 | 术语第一次出现处有一句大白话解释 | 不合格 |
| 11 | script 无表情符号、无括号注释、无 Markdown 标记、无网址 | 不合格（朗读会念出符号） |
| 12 | script 无阿拉伯数字，百分比与年份写成中文读法 | 不合格（否则读出来是「十二点三」或乱读） |
| 13 | script 无「大家好」「今天我们来聊聊」之类主持腔 | 不合格 |
| 14 | script 与 body 事实一致，没有多出 body 里没有的事实 | 不合格 |

## 五、自检脚本

```bash
npx tsx src/server/llm/prompts/_check.ts
```

脚本做两件事：

1. **装配检查**：用样例输入调用四个板块的 `buildUser`，打印 `system` / `user` 长度与前 200 字，
   并断言 system 里写死了「只输出一个 JSON 对象」「禁止用代码块包裹」以及长度、朗读、推断措辞等硬约束。
2. **契约检查**：把四份手写样例 JSON 先 `JSON.stringify` → `JSON.parse` 往返一次，再走各自的
   `schema.parse`，并逐项核对长度区间、script 朗读适配、`meta` 与输入的一致性
   （books 学科、ai-tools 仓库与 Star 数、markets 报价与指数逐字比对、world 恰好 5 条且 rank 为 1..5）。

全部通过时脚本输出「结论：全绿」并以退出码 0 结束；任一断言失败则打印失败项并以退出码 1 结束。
脚本不发起任何网络请求。
