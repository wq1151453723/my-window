# 学习方法设计：为什么这样出稿

这个产品不是「资讯聚合器」，而是按一套学习方法组织的每日输入。四条板块共用同一套出稿纪律。

## 一、单概念拆解（书籍板块）

一本书几十万个字，普通人读完记不住的是零散细节，真正能改变判断的是一两个概念。
所以书籍板块每天只讲一个概念：先给「核心观点」，再给「为什么与你有关」，最后给可迁移的判断标准。
提示词里明确要求「一本书一个核心概念」，避免把一本书写成流水账摘要。

## 二、主动回忆与自我解释（要点速览）

每篇开头先给 3–5 条要点，再给正文。顺序是反过来的：先看要点自己回忆，再读正文核对。
这利用了提取练习（retrieval practice）——回忆比重读更有效。
要点本身也被要求写成「判断句」而不是「名词解释」，逼模型给出可操作结论。

## 三、间隔重复与学科轮换

六个学科（社会学 / 经济 / 历史 / 哲学 / 金融 / AI）按日轮换，每天只上一个学科，
让每个学科都以「短周期、高频次」的方式重复出现，而不是一本书读三周。这正是间隔重复的形态。

## 四、朗读作为复述训练（script 字段）

每篇都有一份独立的朗读稿，与正文同事实但换成口语。朗读的价值有三层：
1. 低保真复述：把书面语转成口头语，暴露「以为懂了其实说不清」的地方；
2. 通勤/家务场景吸收：把阅读时间挪到走路、做饭、洗漱时；
3. 语感与节奏：中文技术内容念出来才知道哪里拗口。

因此提示词对朗读稿有硬约束：不出现 Markdown 标记、括号注释、网址、表情；
数字写成中文读法（「12.3%」→「百分之十二点三」）；长度控制在 400–700 字。

## 五、把「事实」和「推断」分开

金融与局势两个板块最容易出问题，所以输出结构里把推断单独标注：

- 事实：只能来自输入的报价与新闻标题，数字必须与接口返回逐字一致；
- 推断：必须用「可能 / 大概率 / 值得关注」等措辞；
- 每条局势事件带 `confidence`（高 / 中 / 低）与「接下来观察什么」。

这样读者能自己判断哪些是已发生、哪些是判断，而不是被一段流畅的文字带走。

## 六、给普通人的三把尺子

每篇尽量给出可迁移的判断标准，而不是情绪判断：

- 书籍：一把「该按人情办还是按规矩办」的尺子；
- AI 工具：三个自问（数据能不能外传、频次高不高、机器撑不撑得住）；
- 金融：把单日表现和趋势分开，提醒关注汇率与资金成本这类中间变量；
- 局势：把五条新闻按「价格」与「规则」两类归因，看长期攒条件还是短期见效。

## 七、朗读之外的自测

页面没有做笔记和进度（用户明确选择极简），但内容结构已经内置了自测点：
要点速览 → 正文 → 朗读稿，三份内容对应「先回忆、再理解、再复述」三步。
读完只要能复述要点，就说明这一篇拿下了。
